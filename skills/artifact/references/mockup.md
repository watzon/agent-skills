# Mockup

One page that proves an idea. The user opens it, clicks through it, and reacts.

Copy `templates/mockup.html` only if the shell helps. A landing page, game, or tool they will keep can start from a blank `index.html` instead. Load `anti-slop-design` before you write editorial HTML.

## Intake

Restate the idea in one sentence so the user can see you understood it.

If the message names a thing ("a pomodoro timer that tracks streaks"), cover the gaps with stated assumptions and build.

If it names a pain and leaves the product open ("help my team communicate better"), ask two to four pointed questions in one message, then stop. Do not write the page while those are open.

Guessing silently is the failure. A stated assumption is the fallback.

## Fidelity

Name the fidelity in one line of the assumptions, then build that.

| Fidelity | Working means |
| --- | --- |
| sketch | Rough on purpose. Fake data. Reactions go to the idea. |
| clickable | Real flows over canned data. Screens connect the way the product would. |
| wired | A named region hits real data or a real action. Say so. Without that region, clickable is the ceiling. |

Infer it from the ask. Never make the user pick the word.

## Build

Every mockup answers one design question. Write that sentence at the top of the page. If you cannot name it, go back to intake.

Build the smallest page that proves the idea. Make the core interaction work. Mock whatever sits behind it, and label what is fake.

An exploratory ask ("what could this look like?") gets variations in the same page, behind a visible switcher. The variants must disagree in structure, not only in color.

Before publishing, re-read the file once for an unclosed tag, a handler wired to nothing, or a script error. That read is the whole pre-publish check.

**Done when** the question is on the page, the core interaction works, fake regions are labelled, and a revision can land on the same files.

When the user says it is good, list what a real build would still need. Stop proposing changes. If they want it built for real, draft a numbered must / nice / cut list and wait.
